# Verify the E2E test specification

1. Read `nikomi.md`, `dandori.md`, and `e2e.md` for a change whose implementation and verification with `yonabe` are complete. If the specification or implementation has changed, check that the expectations and steps still apply. Report missing steps, environments, data or tools.
2. Use the method in the [project settings and recording instructions](../../osameru/references/format.md). For a new run, prepare the test code and environment, then run `start-e2e` immediately before testing and keep the run ID. Once the results are reset, mark E2E as in progress in `oshinagaki.md`. When receiving results from a completed run or resuming the review, use the run ID already recorded in `e2e.md` and continue from the relevant step.
   - **Playwright.** Use the project's Playwright tests. When needed, prepare tests and assertions for the steps and expectations of each behavior ID before running. Record each ID's assertion result.
   - **Chrome extension.** Use the project's available Chrome extension to run the steps in the specified browser, application and test data. Evaluate the expected text, values or state through assertions or evaluation results from the extension. Distinguish the record of browser actions from the verdict on each expected result. If assertions cannot run, report the missing capability and record the case as unverified.
   - **Manual.** Give the tester the steps in the specification, then collect and record the observed result and verdict for each ID.
3. Record the observed result and verdict from this run for each ID. Use `OK` when the expected behavior was observed and `NG` for a failure. Follow [Recover and finish](recover-and-finish.md) to decide whether to fix the implementation or return to the specification or plan. Record the method, environment, and execution date. When configured and requested for a step, save screenshots in the PBI's `evidence/<run-id>/` directory and link them from the corresponding row. Record interruptions and missing prerequisites in the results.
4. Show the reviewer the steps performed and the verdicts. Once all required checks are marked `OK` and the reviewer explicitly confirms the execution and results, record that confirmation in the same specification with `review-e2e`, the run ID, and the reviewer's name. Report any remaining failed or unexecuted behavior IDs and what needs to be checked next.
5. Update the E2E status in the change directory's `oshinagaki.md`. Once all required checks pass and the reviewer confirms them, report that the design change can be prepared on the work branch with `osameru`.
