# Identify the problem and choose a direction

Read the request, any material the user points to, and relevant parts of the existing system. Start with questions that will most affect later decisions. Find out who has the problem, when it occurs, how people handle it today, and what would count as an improvement. If the user already has a proposed solution, ask about the concrete situation that motivated it.

Ask one decision at a time. Normally present three viable options in order of recommendation, explain why you recommend the first, and accept free-form answers, including alternatives and conditional answers. Ask an open question when you cannot offer concrete options yet. Research facts that are available in the project before asking, and adjust later questions when an answer changes their premise.

Once the direction is clear, ask whether to proceed, investigate further, or set the idea aside. Summarize the problem, scope, chosen direction and rationale, and open questions. If the user wants a Markdown file, fill in the [summary template](assets/saguru-summary.template.md) and save it to the requested location. Start a change when the user gives that summary to `nikomu`.
