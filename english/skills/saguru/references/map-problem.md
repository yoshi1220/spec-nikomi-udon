# Map the problem from a specific situation

Treat the feature first suggested by the user as a candidate solution. When there is a recent incident, trace it to the point where events diverged from expectations. For a new activity with no past cases, start with one intended user and a plausible situation. Record the goal the user chose and identify assumptions that still need evidence from actual use. Start with what the conversation and available evidence already establish. Use the following prompts where they help distinguish between directions.

| Perspective | What to establish |
| --- | --- |
| Who encounters the problem and when | Who does the work, who receives the result, what they were trying to do, and what was different in a similar case that went well. |
| What people do today | What happened immediately beforehand, what the person observed, how they worked around it, and what that cost. Distinguish observations from possible explanations. |
| What is worth addressing | How often the problem occurs, its impact, and the cost of continuing as things are. When figures are unavailable, establish what the concrete case supports. |
| What improvement means | What difference someone could observe in the same situation, which constraints must hold, who takes priority, and what falls outside this effort. |
| Which direction could help | Which cause each option addresses, when it would have no effect, and whether it shifts the burden to someone else. Include a change in working practice when it is a viable option. |

Group questions under the goals they serve. For each, identify the evidence (a source passage or a user's example), what remains unknown, and which decision depends on the answer. Trace prerequisites to dependent decisions so that options sharing a premise can be reconsidered together. Check facts available in the project before asking. Implementation details that cannot change the direction can wait for specification.

For example, if someone asks for application reminders, a useful first question is “What happened the last time an application stalled?” If the approver knew about it but nobody could approve on their behalf, revisit the missed-notification hypothesis. Explore what the cases that needed a substitute approver had in common. Discuss reminder timing once there is evidence that timing could help the work move forward.
