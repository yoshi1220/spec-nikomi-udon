# Project basic design template and writing guidance

From the repository root, read the team-owned `designs/basic-design.template.md` and the skill-maintained `designs/basic-design-writing.md`. The template defines the title, headings, tables, and examples for each function's design body. For manual installations with neither file, use the bundled [standard template](../assets/basic-design.template.md) and [initial writing guidance](../assets/basic-design-writing.md). If the template is missing in a project with an installer record or existing guidance, report the missing template path and wait for restoration.

1. When the project template exists, run `git hash-object --no-filters -- designs/basic-design.template.md` before use and compare it with the leading `<!-- template-blob: <digest> -->` in the writing guidance. Use the guidance if it matches. If the guidance or digest is missing or the digest differs, update the guidance from the latest template. Use the previous guidance and any available template diff as context. Describe what goes in each field, how to write it, and any project instructions that still apply. Map the information covered by the standard headings into the project fields.
2. If a destination is unclear, show what needs to be written and the candidate fields. Ask one question at a time. Before saving the resolved guidance with the new digest, verify the template and guidance still match what you read. If either changed, reread and reconcile against the latest content. Save the new digest only with resolved guidance.
3. Write the target document body using the project template. When an existing design or draft is available, carry forward applicable business rules, evidence, open findings, and manual edits into the matching fields. For passages with unclear destinations, show the original and the options and resolve them before presenting that document for review. Replace examples and prompts with supported content.
4. Check the title, heading order, table columns, and required design information. Check that references resolve from the canonical destination. In `draft-basic-design`, wrap the completed body in the markers recording the target, base, and heading requirement at drafting time and place review items outside the block. Continue with the calling skill's review and incorporation workflow.
