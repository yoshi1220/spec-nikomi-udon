# Identify the problem and choose a direction

1. Read the request, any material the user points to, and relevant parts of the existing system. When resuming, use the specified summary first. Otherwise consult the matching `saguri/<topic>/saguri.md`, the change’s `saguri.md`, or the previous conversation for agreements and reasons for deferring questions. Use [mapping the problem](references/map-problem.md) to identify what is known about each goal and what must be established before choosing a direction.
2. Among questions whose prerequisites are known, ask the one whose answer would change the scope or direction most. Wait for the reply. When a fact is missing, invite the user to describe a concrete case or share evidence. When choosing a direction, normally offer three viable, numbered options in order of recommendation. Explain why the first fits and what choosing each alternative would change. Use fewer options when appropriate and accept free-form alternatives and conditional answers.
3. After each reply, update the working summary in the conversation with what you learned and its basis. Follow [reviewing answers and deciding when to finish](references/review-discovery.md) to revisit decisions whose premises have changed. When you run out of questions, check the summary against the original request. Return to the interview if new gaps or contradictions emerge. Continue for as many questions and rounds as needed.
4. Present the review findings and summarize the outcome the user chose. If they have yet to decide whether to proceed, investigate further, or set the idea aside, offer the viable options and wait for their reply.
5. At the end, follow [keeping the summary](references/keep-summary.md) to ask one question about where to save it or whether to keep it in the conversation. Honor a choice the user has already made.
