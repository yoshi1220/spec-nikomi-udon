# 実装して検証する

## 一作業ずつ進める

1. 作業 ID、予定する成果、前提の作業 ID、完了条件、関連する受け入れ条件を読む。前提作業はすべて完了し、その結果が有効であることを着手前に確かめる。未完了の前提があれば、後続作業を見送り、理由と前提 ID を記す。着手できる別の作業は計画順に進める。
2. 既存の入口や類似実装、テストを調べ、要件に合う実装方法やコードを再利用する。合意済みの範囲内で別の方法を採る場合は、理由を計画に記す。コードを変更する場合は、期待する振る舞いを捉えるテストを先に用意することを基本とする。既存のテストで確認できる場合は活用し、実装前の失敗を確認する場合は想定した理由で失敗しているかを見る。
   - 計画した入力で、変更する振る舞いと影響を受ける既存の振る舞いを確かめる。新規・既存のテストでは、仕様に反した結果ならアサーションが失敗するかを確認する。手動確認では、同じ違いを手順の観測項目から判定できるかを確認する。計画内で補える不足はテストや手順を補い、計画の確認方法を変える必要があれば [失敗対応と完了判定](recover-and-finish.md) に従う。
3. 仕様と作業の成果を満たす範囲で変更する。完了条件に記載されたテストや手動確認と、影響する既存テスト、該当するプロジェクト所定の検証を実行する。今回の編集で、すでに完了した作業や合格した条件の根拠も影響を受ける場合は、[失敗対応と完了判定](recover-and-finish.md) に従って記録を更新し、必要な確認をやり直す。失敗や食い違いも同じ手順で扱う。
4. 完了条件を満たしたら、最新の `dandori.md` で作業 ID と内容を確認し、チェック欄を更新して、実行した確認と結果を保存する。仕様、計画の状態、作業の前提や完了条件に変更があれば、着手・再開の準備に戻って照合する。次の作業へ進む前に保存内容を見直す。完了に必要な確認が失敗・未実施なら、その理由を残してチェックを付けない。

## 受け入れ条件を検証する

- 受け入れ条件 ID ごとに、確認に必要な作業がすべて完了していることを確認する。作業の実行結果を再利用するときは、使った入力と実際に照合した結果が、その条件の確認方法と期待結果を満たすか確かめる。複数の作業を組み合わせた振る舞いは、必要な作業がそろった状態で確認する。
- `dandori.md` の該当する行に、テスト名・コマンドまたは手動確認の手順、実際に観測した結果を記録する。仕様の期待結果と一致したことを確認してから合格とする。失敗、未実施、再確認待ちは理由とともに示す。
- 条件がまだ検証できない場合は、待っている作業 ID や不足した前提を記す。計画にある方法で検証を始められるようになったら、未実施や再確認待ちの条件を確認する。
