# E2E テスト仕様書に沿って確認する

1. `yonabe` の実装・検証を終えた変更の `nikomi.md`、`dandori.md`、`e2e.md` を読みます。仕様または実装が変わっていれば、期待結果と手順が現行の変更に対応するかを確かめます。手順、環境、データ、ツールが足りなければ、不足している前提を報告します。
2. [プロジェクト設定と記録方法](../../osameru/references/format.md) に従い、設定のテスト方法を使います。新たにテストするときは、テストコードと環境の準備を済ませ、テストの直前に `start-e2e` を実行して実行 ID を控えます。結果欄がリセットされたら、`oshinagaki.md` に E2E が実施中であることを記録します。実施済みの結果を後から受け取る場合や担当者の確認を再開する場合は、`e2e.md` にある実行 ID を引き継ぎ、該当する手順から続けます。
   - **Playwright**。プロジェクトの Playwright テストを使います。必要なら各振る舞い ID の手順と期待結果に対応するテストとアサーションを用意してから実行します。各 ID のアサーションの結果を確認して判定を記録します。
   - **Chrome 拡張**。利用できるプロジェクトの Chrome 拡張で、指定されたブラウザー、画面、データに対し各手順を実施します。期待する文言、値、状態などを拡張のアサーションや評価結果から自動で確かめます。画面を操作した記録と、期待結果を満たした判定を区別します。アサーションを実行できないケースは必要な機能を示し、未確認として記録します。
   - **手動テスト**。担当者に仕様書の手順を案内し、各 ID の観測結果と合否を受け取って記録します。
3. 各 ID に今回の実施結果と判定を記録します。期待した振る舞いを確認できた項目を `OK`、不合格を `NG` とします。不合格の原因に応じて、[失敗対応と完了判定](recover-and-finish.md) の手順に沿って、実装を修正するか、仕様や計画の確認に戻ります。テスト方法、環境、実施日も記録します。キャプチャが有効で指定された場面があれば画像を PBI 内の `evidence/<実行ID>/` に置き、対応する行にリンクします。途中失敗や準備不足も結果に示します。
4. 実施した手順と各 ID の判定を担当者に提示します。必須項目がすべて `OK` となり、担当者が実施内容と結果を明示的に確認したら、実行 ID と確認者名を指定して `review-e2e` を実行し、同じ仕様書に確認を記録します。失敗や未実施が残っている場合は、該当する ID と次に必要な確認を伝えます。
5. 変更用ディレクトリの `oshinagaki.md` に E2E テストの状況を記録します。必須項目の合格と担当者の確認がそろったら、`osameru` で作業ブランチに反映できることを報告します。
