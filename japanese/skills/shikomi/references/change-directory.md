# 案件ディレクトリを用意する

利用者が既存案件を指定したら、その案件のブランチとディレクトリを使う。指定がなく、現在の `feature/<変更名>` で同じ案件を続ける場合は `specs/<変更名>/` を使う。ブランチがすでにあり、このディレクトリだけがなければ作る。別の案件との対応が曖昧なら、書き込む前に対象を確認する。

新しい案件なら内容を表す短い名前（例 `export-csv`）を決め、次の手順で採番する。別の案件のブランチを起点にしてよいか分からない場合は、作成前に確認する。

1. 設定済みのリモートがあれば `git fetch --all --prune` を実行する。失敗した場合は理由を示し、リモートの最新の連番を確認できていないと伝える。取得済みの情報で続けるか中止するか利用者に尋ね、続行の回答を得てから次へ進む。リモートが未設定なら、ローカルの情報で採番する。
2. 対象リポジトリを作業ディレクトリにして、同梱の [start_change.py](../scripts/start_change.py) を Python 3 で実行する。引数には変更名を一つ渡す。スクリプトはローカルブランチ、取得済みのリモートブランチ、`specs/` 配下の既存ディレクトリを調べ、その最大番号の次を使う。出力されたブランチとディレクトリを使う。異常終了したときは、作業ブランチとディレクトリの状態を調べてから再試行を判断する。
