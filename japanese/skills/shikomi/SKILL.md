# 変更の仕様を起こして詰める

利用者の要件や PBI から、変更の目的を把握する。検討のまとめは、指定されたパスから読む。パスの指定がない場合に自動で参照するのは、対象 feature の `specs/<変更名>/saguri.md` がある場合に限る。既存の仕様案から再開する依頼では、その `shikomi.md` を使う。

[たたき台を用意する手順](references/prepare-spec.md) に従い、新規作成または再開の準備をする。続いて、[明確化の手順](references/clarify-spec.md) と、そこで指定する 2 つの参照ファイルを必ず読む。設計ツリーに沿ってラウンドごとに一問ずつ確認し、合意をその都度保存する。重要な論点ごとに結論が出るか、保留理由が記録されるまで再点検を繰り返す。利用者の最終確認後は、案件のフローに応じて、基本設計書案を作る `shitagaki` または実装計画を立てる `dandori` に引き継ぐ。
