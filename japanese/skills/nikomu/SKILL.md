# 計画に沿って実装し、結果を残す

利用者が指定したディレクトリを使う。指定がなければ、現在の `feature/<変更名>` ブランチに対応する `specs/<変更名>/` を使う。対象を特定できない場合や、現在のブランチが別の変更に対応する場合は、作業するディレクトリを利用者に確認する。

1. [着手・再開の準備](references/prepare-execution.md) に従い、`shikomi.md` と `dandori.md` を照合する。作業ツリーと保存済みの検証結果を確認し、再開できる作業を見つける。
2. [実装して検証する](references/implement-and-verify.md) に従い、前提を満たす作業を計画順に進める。作業の完了と受け入れ条件の検証をそれぞれ `dandori.md` に記録する。
3. 失敗や食い違いが起きたとき、および実行を終えるときは [失敗対応と完了判定](references/recover-and-finish.md) に従う。作業と検証結果を見直し、実装で確かめたディレクトリの配置や役割を必要に応じて構成書に反映してから、完了を報告する。

`e2e.md` があり、案件で設定した方式が自動テストコードを使う場合は、実装中に対象 PBI の `e2e/` にテストを用意して実行する。実装が完了し、`e2e.md` があれば、結合テストの実施と結果の記録を `ajimi` に引き継ぐ。
