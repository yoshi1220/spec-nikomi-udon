# 計画に沿って実装し、結果を残す

対象ディレクトリは利用者の指定を使う。指定がなければ、現在の `feature/<変更名>` ブランチに対応する `specs/<変更名>/` を使う。対象を特定できない場合や、別の変更のブランチにいる場合は、利用者に作業先を確認する。

1. [着手・再開の準備](references/prepare-execution.md) に従い、`shikomi.md` と `dandori.md` を照合する。作業ツリーと保存済みの検証結果を確認し、再開できる作業を見つける。
2. [実装して検証する](references/implement-and-verify.md) に従い、前提を満たす作業を計画順に進める。作業の完了と受け入れ条件の検証をそれぞれ `dandori.md` に記録する。
3. 失敗や食い違いが起きたとき、および実行を終えるときは [失敗対応と完了判定](references/recover-and-finish.md) に従う。影響を受ける作業と検証結果を見直し、現在の変更に対してすべて確認できてから完了を報告する。

`e2e.md` がある変更では、実装完了時に `ajimi` を案内する。
