# 着手・再開の準備

## 仕様と計画を照合する

1. 対象の `shikomi.md` と `dandori.md` を読み、計画の参照先が今回の仕様であることを確かめる。仕様に `<!-- shikomi-review: confirmed -->` があり、実装や受け入れ検証を妨げる未確認事項が解消していれば次へ進む。確認が必要なら、該当箇所と利用者に確認してほしい内容を示して明確化に戻る。
2. 状態マーカーがある計画では、先頭に `<!-- dandori-plan: ready -->` が一つだけあることを確かめる。保留中や不正な状態は計画に戻る。マーカーがない旧形式も、以下の内容を照合して使えることを確認する。
3. 計画が現行の仕様に対応していることを確かめる。作業 ID と受け入れ条件 ID の重複、存在しない参照、前提より先に並ぶ作業、確認方法がない受け入れ条件を調べる。実行順、作業範囲、確認方法を修正する必要があれば、該当する ID を示して計画に戻る。

現行計画の作業を記載順に[一時 GraphML の操作](../../dandori/references/work-graph.md)の `tasks FILE --print-order` に渡し、出力と計画順を照合する。確認表に従って受け入れ条件をノードとして加え、必要な作業から条件へ `verifies` を張る。再開時は最新の計画と確認表から組み直す。

## 変更の途中から再開する

- 関連するプロジェクト指示、全体指針、既存仕様、コード、テストを読む。作業ツリーの差分を見て、今回の途中実装、すでに完了した変更、別件の変更を見分ける。既存の変更を保ち、対象が重なって扱いを決められないときは利用者に確認する。
- チェック済みの作業と記録済みの合格結果を読み、その結果を支えたコード、依存作業、検証手順が現在も有効か確かめる。対象の変更が後から入った場合や根拠を確かめられない場合は、[失敗対応と完了判定](recover-and-finish.md) に従って記録を更新し、影響を受けた確認をやり直す。
- `ajimi` から不合格の報告を受けたら、振る舞い ID と期待・観測結果を今回の検証結果として扱う。すでに完了している作業も含め、影響する作業と受け入れ条件を特定し、上の手順に従って記録を更新する。
- 自動 E2E のテストや実行コマンドの不足を `ajimi` から引き継いだ場合は、完了済みの計画でも該当 ID の検証を再開する。旧配置のテストを使える場合は、既存の利用箇所を保ち、今回の PBI の `e2e/` から実行できるようにしてコマンドを確かめる。
- 有効な完了記録を引き継ぎ、未完了のうち前提を満たす作業から始める。途中実装が見つかったら、計画の完了条件に照らして残りを確かめる。作業がすべてチェック済みでも、未検証や再確認待ちの受け入れ条件があれば確認を続ける。
