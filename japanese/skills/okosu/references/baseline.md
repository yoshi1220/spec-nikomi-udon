# 調査・再開・文書レビュー

## 調査する版と機能一覧

- 利用者が指定したブランチ・タグ・コミットをコミット ID に解決する。指定がない場合、初回は現在の `HEAD`、再開時は全体指針に保存したコミットを使う。PR の取り込み先が分かっていて調査対象のコードが異なる場合は、どの版を現行として扱うか利用者に確認する。コミットに含まれるコード・設定・テストを読み、作業ツリーと内容が異なる場合は `git show <コミット>:<パス>` などで調査対象を読む。導入の文書差分に利用者の別作業を含めない。
- 画面、API、バッチなどの入口から利用者や連携先が観測できる機能を洗い出す。設定、データの流れ、呼び出し、既存テストをたどり、関係の両端・種類・方向が分かるものを根拠とともに記す。機能の親子関係は業務上の分類の根拠がある範囲で付ける。入口や連携を調べきれない場合は確認できた範囲と残りを示す。
- 根拠はリポジトリ相対パスとシンボルや設定キー、必要に応じて対象版の行番号で特定できるようにする。実行時の設定値や外部システムの動作が確認できない場合は、分かっている条件と残る不明点を記す。既存文書と食い違う場合は双方の根拠を示し、解消済みとして扱う前に利用者の判断を記録する。

調査版から確認できた機能の包含・呼び出し・データ連携は[一時 GraphML の操作](../../dandori/references/work-graph.md)で整理し、辺に根拠のパスとシンボルを付ける。包含だけを `order FILE contains` で検証する。改修や版変更の影響は関係の向きに合わせてたどる。たとえば呼び出し先の契約変更では `affected FILE 変更先ID --via calls --reverse` で呼び出し元の候補を抽出し、当該版のコードで確かめて整備範囲に反映する。

## 判断を保存して再開する

`designs/system-overview.md` に「既存案件の導入」節を一つ設け、次を保存する。既存の節は更新して使う。

| 項目 | 記録と扱い |
| --- | --- |
| 調査対象の版 | 調査したコミット ID。確認済みの状態はこの版と一覧の内容に対応する。 |
| 機能一覧の確認 | 下書きは「確認待ち」。範囲の判断に影響する不明点が解消し、利用者が一覧全体を明示的に確認したら「確認済み」とし、確認内容と照合値を記す。照合値は、確認した一覧・関係の節を見出しごと文書順に取り出して連結し、改行を LF にそろえた UTF-8 の SHA-256 とする。「既存案件の導入」節は照合から外す。 |
| 基本設計書の整備範囲 | 選択前は「未選択」。選択後は整備方針と、合意した機能の一覧または全機能であることを記す。改修対象と影響先を選んだ場合は、起点となる改修と機能の関係も記す。 |
| 残る不明点 | 範囲の判断を止める点と、範囲を決めた後でも確認できる点を、理由・影響・参照元とともに残す。 |

中断前に状態と合意済みの判断を保存する。再開時は一覧・選択範囲・作成済みの文書を読み、確認済みの照合値を現在の一覧と照合する。調査する版を変える場合は、旧版との差分から機能一覧・依存関係・範囲・設計書への影響を確認する。一覧の確認に影響する変更があれば「確認待ち」に戻す。範囲に影響する変更があれば、以前の範囲と理由を残して再選択を待つ。確認済みの照合値がない場合や、照合値が変わって影響の有無を判断できない場合は「確認待ち」に戻す。両方に影響がなければ確認と選択を引き継ぎ、調査版と照合結果を更新する。

## 基本設計書と導入専用の文書 PR

- 案件書式の対応する欄に目的・対象範囲、業務ルール、入力・出力、正常時・異常時の振る舞い、根拠・参照先を記す。該当する権限や外部連携も記す。前提、操作や入力、観測できる結果を根拠のある範囲で記し、実動作でしか判断できない箇所は未確認とする。既存テストは記述されている期待を根拠に使い、観測結果として扱うにはその版での実施記録を要する。
- 機能ごとに既存の正本があればそのパスと適用される記述を引き継ぎ、変更をレビューできるよう差分にする。既存案や手修正があれば比較して引き継ぐ。各文書にはテンプレートの本文を Markdown として置く。今回の作業は `shikomi.md` を必要とせず、PBI の E2E を前提にする `osameru apply` を経由せずに、文書 PR 用のブランチに文書を用意する。
- PR を用意する前に、合意した機能と設計書が対応していること、分析版と根拠から記述を検証できること、未確認が明示されていることを確かめる。取り込み先に対する PR 全体の差分を確認し、導入用の文書だけを含める。取り込み先のコードや既存文書が変わっていれば影響を照合し、該当する一覧・確認・設計書を更新してからレビューに進む。PR の説明には調査版と対象範囲、主な根拠、未確認事項、文書への参照を含める。マージ後の変更では、全体指針と正本を `shitagaki` の参照入力として使う。
