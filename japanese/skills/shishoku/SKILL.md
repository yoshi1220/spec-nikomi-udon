# システム全体のテストを実行する

1. ルート `e2e/` のシナリオと実行手順を読み、今回の対象 ID を決める。指定なしならルートの全件、指定ありなら ID・機能名・ファイル等をシナリオと照合して該当するものだけを選ぶ。該当なしならその旨を伝えて終了する。解釈によって範囲が変わる場合は候補を示して確認する。シナリオやテストが不足していれば、該当箇所を [盛りつけ](../moritsuke/SKILL.md) に返す。
2. `osameru` の `scripts/osameru.py settings` で案件の E2E 方式と撮影設定を読み、利用できる環境・基盤・データを対象 ID ごとの前提と照合する。実行できる ID を特定し、前提がそろわない ID はその理由とともに未実施として記す。実行ごとに新しい一意の実行 ID を割り当てる。結果と証跡の既定の保存先はリポジトリ直下の `evidence/system/<実行ID>/`。案件の保存先を使う場合も、ランナーが消去する出力先（Playwright の `outputDir` など）と、テストの収集・PBI の入力照合の対象から外す。今回選んだシナリオに撮影場面があり、設定が有効なら、その実行専用の保存先をテストへ渡す。それ以外は撮影用の環境変数を外して実行する。[画面の確認と撮影条件](../e2e-authoring/SKILL.md) を使う。
3. 自動テストでは、ランナーが収集したテストと実行可能な ID が一致することを確かめ、同じ選択条件で実行する。ルートの全件を指定した場合も、実行対象はシステム全体のテストに限る。手動またはブラウザ操作では、選んだシナリオに沿って期待結果と観測結果を比べる。途中で終了したりスキップしたりしたケースは、該当する ID を未実施または未確認として記録する。
4. 実行のレポート（既定は出力先の `results.md`）に実行 ID・対象範囲・環境・実施方法と、各対象 ID の期待結果、観測結果、合否、今回取得した証跡へのリンクを記録する。判定が基盤に依存する場合は実際に使った基盤を記す。実基盤が必要なケースを代替基盤で試した場合は観測値を残し、計画したケースは未実施とする。使用基盤が不明ならその ID は未確認とする。前提どおりに実施して期待と異なれば NG とする。必要な画像を保存できなかった場合は理由を記し、必要な証跡がそろうまでその ID の合格を確定しない。コマンドの異常終了は実行の失敗として記録する。影響する ID（特定できなければ実行した全 ID）の観測値と判明した NG を残し、検証できなかった結果は未確認とする。部分実行では今回の対象と結果を明示する。
