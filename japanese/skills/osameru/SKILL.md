# 仕様を正本に納める

`nikomu` で実装し、`ajimi` で E2E テストの合格と担当者の確認を記録した変更を対象とします。[受け渡し形式と CLI](references/format.md) に従い、作業ブランチに正本と改訂履歴の更新を用意します。

1. 利用者が指定した `specs/<変更名>/` を使います。指定がなければ現在の `feature/<変更名>` から対象を選びます。作業ブランチと対象の変更が対応すること、`shikomi.md` と `shitagaki.md` が存在することを確認します。
2. `shikomi.md`、`shitagaki.md`、`e2e.md` を照合します。設計案の必須項目、未確認事項、E2E の範囲を確認します。要件と実装・設計が食い違う場合や、設計の根拠が足りない場合は、該当箇所を示して利用者に一問ずつ確認します。
3. CLI の `apply` を使い、変更理由を `--reason` で渡します。CLI が、現在の変更に対する必須 E2E テストの合格と担当者の確認済み記録を照合します。反映できなければ理由を伝え、設計の手直しや再確認が必要な工程へ戻ります。
4. 正本と改訂履歴の差分を読み直します。変更用ディレクトリの `oshinagaki.md` に反映先と、作業ブランチに反映した状態を記録します。実装と設計書の更新を同じ PR でレビューできることを報告します。設計書案のレビューを終え、同じ PR をマージした時点で正本の更新が完了します。PR の送信やマージは利用者の依頼を受けて行います。
