# まとめの保存と引き継ぎ

終了時は、次のうち利用できる選択肢を上から順に番号付きで示し、回答を待つ。「保存して」とだけ依頼されていれば、第一候補を使う。利用者が保存先を指定した場合や、会話だけに残すよう指定した場合は、その指定に従う。

- **リポジトリ直下の `saguri/<相談名>/saguri.md` に保存する（推奨）**。ブランチを作る前から相談単位で残せる。内容を表す短い相談名を付け、選択肢には実際のパスを示す。同じ相談の続きならそのファイルを更新する。別の相談と名前が重なる場合は区別できる名前を選ぶ。
- **既存の feature ブランチに対応する `specs/<変更名>/saguri.md` に保存する**。この相談に対応する `feature/<変更名>` がすでにある場合に提示する。そのブランチの作業ツリーで、`shikomi.md` や `dandori.md` と同じディレクトリに置く。
- **この会話だけで使う**。まとめを会話に返す。同じ会話で `shikomi` を始めれば、その合意を引き継げる。

保存する場合は、必要に応じて指定先のディレクトリを作り、[まとめのテンプレート](../assets/saguri.template.md) を使って書く。その場所にファイルがあれば、先に内容を読む。同じ相談の続きなら、判断が変わった箇所を更新し、今も有効な合意を残す。自動で付けた相談名が別件と重なったら、名前を変える。利用者が選んだパスで重なった場合は、別の保存先を提示して回答を待つ。

保存できたらパスを伝える。保存に失敗した場合は、理由とまとめを会話に残す。リポジトリ直下のまとめを後で `shikomi` に渡すには、そのパスを指定するか、対象 feature の `specs/<変更名>/saguri.md` に移しておく。`saguru` のまとめを保存するための採番や新規ブランチの作成は不要。
