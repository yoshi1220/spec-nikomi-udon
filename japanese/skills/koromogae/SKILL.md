# 基本設計書を衣替えする

1. 共有ブランチの対象版と、利用者が採用する案件書式を特定する。既定の対象は `designs/specifications/` 配下の機能別基本設計書。改訂履歴、画面項目定義、その他の文書は対象外。区別できないものは確認する。利用者が範囲や業務・機能ごとのまとまりを指定したら、その単位で対象一覧を作る。
2. 一つのまとまりを一つの書式移行専用の文書PRとして準備する。既定は対象全件で一つ。共有側の版を元にした専用の作業ブランチで、元の文書パスを維持して本文を移す。別作業の変更がある場合は、書き込む前に作業ツリーを分け、採用する書式と作成方針を引き継ぐ。作業先で[案件の基本設計書式と作成方針](../shitagaki/references/basic-design-format.md)を解決する。共通の書式・作成方針が移行に必要なら関連差分として示し、複数のPRで競合しないよう一度だけ取り込むか共通の前提にする。
3. 各文書の業務ルール、振る舞い、根拠、未確認事項、手修正を新しい欄へ引き継ぐ。新しい欄の情報が元文書にない場合は未確認と示す。移し先が不明な原文と候補を示して確認し、判断できる文書は下書きを進める。中断時はブランチ、元の版、書式の照合値、対象一覧、回答、確認待ちを利用者に示し、再開時は差分と照合する。元文書または書式が変わっていたら影響する文書を再照合する。
   構造管理を導入した案件は、現行索引と対象範囲の文書を照合し、未移行の基本設計書も含める。節の固定IDを見出しと一緒に引き継ぐ。`structure/`・`history/` は書式変換の対象から除く。レビューするまとまりごとに[文書専用の構造更新](../osameru/references/structure.md)で、索引に登録済みの文書の位置と該当ノードの履歴を更新する。
4. まとまりの全件が揃ったら、元の版と移行後を比べ、設計上の意味と該当する記述が引き継がれ、対象外の文書や実装が差分に含まれていないことを確かめる。同じ書式に移行済みで差分のない文書はその旨を示す。対象一覧、移行差分、主な欄の対応、新しい欄で確認が必要な情報をPRの説明にまとめる。共有側で対象文書が改修されていれば最新の記述を取り込んで再確認する。PRをマージした時点で正本に反映する。送信やマージは利用者の依頼を受けて行う。
