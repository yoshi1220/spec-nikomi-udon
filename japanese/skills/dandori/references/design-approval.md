# 計画前の設計承認

確認済みの変更仕様など、通常の計画着手条件を確認する。設計承認の判定には [お品書きの準備・移行手順](../../osumitsuki/references/index.md) に従い、対象PBIの `status` を読む。

- `off` は承認欄を作らず計画へ進む。通常起動で `approved` または `emergency` なら計画へ進む。記録済みの緊急理由の再入力、設計版の再照合、PRへの再照会は不要。
- 利用者が緊急指定と省略理由を伝えたとき（例 `$dandori --emergency 本番障害の復旧を優先`）、緊急指定を案件の所定の役割から例外の了承を得た旨の申告として扱う。承認が有効で当該PBIにまだ緊急記録がなければ、[approval.py](../../osumitsuki/scripts/approval.py) の `emergency --reason "理由"` でお品書きに記録し、保存成功後に計画へ進む。理由がなければ理由だけ尋ねる。すでに緊急対応なら保存済みの理由を使う。
- 通常起動で `pending` の場合は、対象の設計案を示し、承認を得て [osumitsuki](../../osumitsuki/SKILL.md) で記録するよう案内する。計画を保留し、承認記録後に同じPBIから再開する。
