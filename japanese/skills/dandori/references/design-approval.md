# 計画前の設計承認

まず、変更仕様が確認済みであることなど、通常の着手条件を確認する。設計承認の状態は、[お品書きの準備・移行手順](../../osumitsuki/references/index.md) に従い、対象 PBI の `status` で確認する。

- `off` は承認欄を作らず計画へ進む。通常起動で `approved` または `emergency` なら計画へ進む。記録済みの緊急理由の再入力、設計版の再照合、PRへの再照会は不要。
- 利用者が緊急対応とその理由を指定した場合（例 `$dandori --emergency 本番障害の復旧を優先`）、案件で例外を認める役割の担当者から了承を得たという申告として扱う。設計承認の設定が有効で、対象 PBI に緊急対応の記録がなければ、[approval.py](../../osumitsuki/scripts/approval.py) の `emergency --reason "理由"` でお品書きに記録する。保存できたら計画へ進む。理由がなければ理由だけ尋ねる。すでに緊急対応なら保存済みの理由を使う。
- 通常起動で `pending` の場合は、対象の設計案を示し、承認を得て [osumitsuki](../../osumitsuki/SKILL.md) で記録するよう案内する。計画を保留し、承認記録後に同じPBIから再開する。
