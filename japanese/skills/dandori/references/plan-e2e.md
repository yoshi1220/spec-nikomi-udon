# 結合テスト仕様書の形で E2E テストを計画する

1. `shitagaki.md` の基本設計書案と `nikomi.md` の受け入れ条件を読みます。今回変える振る舞いと、その影響を受ける振る舞いを選びます。正常時と失敗時を含め、どの条件をどの手順で確認できるかを明示します。テストに必要な環境やデータには、計画中に用意する作業を結び付けます。
2. [E2E テスト仕様書のテンプレート](../assets/e2e.template.md) に沿って、変更用ディレクトリの `e2e.md` を作成します。確認する振る舞いごとに重複しない ID を付け、設計の該当箇所や、対応する受け入れ条件 ID を示します。前提・手順・期待結果を埋め、実施結果は未実施として始めます。画面で確認する結果があり、プロジェクト設定でキャプチャが有効なら、必要な取得場面を指定します。表の構造は [CLI の受け渡し形式](../../osameru/references/format.md) を保ちます。
3. 計画の見直しでは既存の `e2e.md` を読み、同じ振る舞いの ID を引き継ぎます。影響を受ける手順・期待結果・実施結果を見直し、再確認が必要な結果を示します。対象範囲の過不足と、各 ID の期待結果を実際に判定できることを確かめたら、[実装計画の検証](write-plan.md#保存前後に照合する) に戻ります。
