# 実装した変更を E2E テストで確かめる

利用者が指定したディレクトリを使う。指定がなければ、現在の `feature/<変更名>` ブランチに対応する `specs/<変更名>/` を使う。対象を特定できない場合や、現在のブランチが別の変更に対応する場合は、作業するディレクトリを利用者に確認する。

- `evidence/<実行ID>/recovery.md` に復旧中または利用者の対応待ちと記録されていれば、[復旧手順](references/recover.md) に沿って、記録された段階から再開する。
- 通常は [E2E テスト手順](references/run-e2e.md) に従い、現行の仕様・計画とテスト項目を照合する。設定した方式で対象 PBI の結合テストを実施する。自動テストコードを使う場合は、`nikomu` が対象 PBI の `e2e/` に用意したテストを再実行する。結果を記録したら、今回の実行 ID に対応する結果を見て、復旧に進むか担当者に確認を求めるかを判断する。
- `verify-e2e` で現行の変更に対する合格と、案件設定に応じた必要な記録を照合できたら、`osameru` に進めることを伝える。
