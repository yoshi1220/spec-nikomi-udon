# 案件の基本設計書式と作成方針

リポジトリ直下を基準に、案件が編集する `designs/basic-design.template.md` と、スキルが更新する `designs/basic-design-writing.md` を読む。書式は標題・見出し・表・記入例など、機能別の基本設計書の本文を定める。手動導入で両方ともなければ、同梱の[標準書式](../assets/basic-design.template.md)と[初期の作成方針](../assets/basic-design-writing.md)を使う。導入記録または作成方針があり、案件書式が見つからない場合は、書式のパスを示し、復元を待つ。

1. 案件書式がある場合、使う直前に `git hash-object --no-filters -- designs/basic-design.template.md` を実行し、作成方針の先頭にある `<!-- template-blob: <照合値> -->` と照合する。値が一致すればその方針を使う。方針または照合値がない場合や一致しない場合は、最新の書式から作成方針を更新する。以前の作成方針と利用できる書式の差分を参考にする。各欄の役割、書き方、現在の書式に適用できる案件の指示を記す。標準の見出しに対応する情報は、案件の欄に割り当てる。
2. 記入先を判断できない場合は、書くべき内容と候補の欄を示し、一問ずつ確認する。確定した方針は、保存直前に書式と方針の元の内容を照合してから、新しい照合値と一緒に保存する。途中でどちらかが変わった場合は読み直し、最新の内容からやり直す。確認待ちの間は未確定の方針に新しい照合値を付けない。
3. 対象文書の本文を案件書式で作る。既存文書や案があれば、維持する業務ルール、根拠、未確認事項と手修正を対応する欄へ引き継ぐ。移し先が判断できない記述は、原文と候補を示して確認し、対象文書をレビューに回す前に解決する。例や記入指示は実際の根拠に置き換える。
4. 表題・見出し順・表の列と、必要な設計情報を照合する。正本から参照をたどれることを確認する。`shitagaki` は本文の外側に反映先・元版・作成時の見出し条件を示すマーカーを付け、レビューで確認する事項もブロックの外側に記す。各スキルの通常の確認・反映手順へ戻る。
