# システム全体の指針を用意する

`--file <パス>` で指定された要件定義資料、またはその場で渡された説明文を読む。ファイルの指定があり、資料を読み取れない場合は、読めない理由を伝えて続けるために必要な入力を尋ねる。

- [全体指針のテンプレート](assets/system-overview.template.md) を使い、`designs/system-overview.md` に目的、対象範囲、主要機能、システム構成、外部連携、全体に共通する制約をまとめる。ファイルを読んだ場合は参照元も記す。判断に必要な情報が足りない箇所は「未確認」とする。
- `designs/repository-structure.md` には [構成のテンプレート](assets/repository-structure.template.md) を使う。入力に記載があれば、記入案内をプログラムのディレクトリ構成と分かる範囲での役割に置き換える。記載がなく、新規作成する場合は、利用者向けの記入案内を残す。
- 既存の同名文書があれば読み、明示された更新を適用する。既存の記載と入力が矛盾する箇所は、利用者が判断するまで未確認として扱い、既存の内容を保つ。

深掘りや判断の確認は一問ずつ行う。原則３つの案を推奨順に並べて最初の案を推す理由を添え、自由入力も受け付ける。案を提示できないときは、自由に答えられる質問にする。

利用者が導入設定も求めている場合は、利用するエージェントの指示ファイル（例 `AGENTS.md`、`CLAUDE.md`）に、作成した文書の参照先と読む場面を追記するか、対象ファイルを示して確認する。既定の選択肢は「はい」とする。了承を得た場合に既存の指示を保ったまま追記し、同じ案内があれば重複させない。
