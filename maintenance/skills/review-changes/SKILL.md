# 前回コミットからの差分を見直す

リポジトリの作業ガイドと今回の依頼を確認する。ベースは現在の `HEAD` とし、別の比較元が指定されていればそれを使う。

1. リポジトリのルートで `git status --short`、比較元からステージまでの差分（通常は `git diff --cached`）、`git diff`、比較元から作業ツリーまでの差分（通常は `git diff HEAD`）を確認する。作業ツリーで相殺される変更を見落とさないよう、ステージ済みと未ステージを個別にも読む。`git ls-files --others --exclude-standard` で未追跡ファイルを列挙し、内容を読む。初回コミット前で比較元がない場合は、ステージ済み・未ステージ・未追跡を確認する。無視対象の未追跡ファイルは差分に含めない。作業ガイドが指定する非公開資料は照合にだけ使う。
2. 変更を依頼内容と突き合わせ、影響を受ける参照元や後続の工程までたどる。公開スキルは英語版と日本語版で入出力、手順、完了条件を照合する。README の導入手順、スキル間の相対リンク、テンプレート、採番スクリプトが導入先でつながるかを確かめる。
3. 実際に食い違う箇所、依頼の範囲を超えた変更、必要なのに抜けた処理を特定する。指摘にはファイルと該当箇所、起こり得る結果を添える。修正も依頼されていれば、根拠のある修正を行う。判断が必要な点は理由とともに残す。
4. 修正後は差分を取り直す。ステージ済みの内容が作業ツリーと異なる場合は、そのままコミットすると入る内容を確認する。`git diff --check` と `git diff --cached --check` で空白を確認し、未追跡ファイルにも同じ観点を適用する。変更に応じてリンクの検査や一時環境での動作確認を行う。
5. 最後に、ステージ済みの内容と、これから追加する変更の両方に非公開情報が混入していないか確認する。
   - 認証情報、個人・顧客の情報、内部 URL、ローカルの絶対パスが、本文、設定、例、コメント、添付物に含まれていないか調べる。
   - Git のユーザー名、メールアドレス、アカウント ID と、自動生成物に入りやすい実名、OS のユーザー名、コンピューター名が差分に混入していないか調べる。今回のコミットに記録される作者・コミッターの名前とメールアドレスは `git var GIT_AUTHOR_IDENT` と `git var GIT_COMMITTER_IDENT` で確認し、対象に既存のコミットがあればそのメタデータも確認する。OS や端末名から補われた値、公開を意図したクレジット、公開可否が未確認の情報を区別する。リモート URL に認証情報が埋め込まれていないかもローカルで確認する。
   - 手元の非公開資料と公開候補を照合し、未公開の構想、検討案、調査メモの情報が、要約・翻訳・例・リンクを通じて公開されないか確認する。
   - `git ls-files` と `git check-ignore` を使い、非公開ファイルが追跡やステージの対象に入っていないことと、意図した除外が効いていることを確かめる。追加・移動したファイルやリンクの参照先も確認する。
   - 確認はローカルで行う。疑わしい箇所はファイルと行、情報の種類だけを示し、値や非公開資料の内容は出力しない。公開可否が分からなければ要確認として残す。漏洩箇所を修正した場合は、修正後の差分を再確認する。

修正した点、残る指摘、確認できた範囲を報告する。ステージング、コミット、プッシュは、それぞれ依頼された場合に行う。
